● Robson v2.5.0 Release Notes

  Release Date: 2026-05-09
  Type: Minor Release (Feature + Security Enhancement)
  Status: Production Ready

  ---
  🎯 Overview

  Robson v2.5.0 introduces Policy I3 (Reverse Reconciliation Invariant), completing the symmetric position lifecycle protection system. This
  release addresses a critical asymmetric reconciliation gap where robsond could maintain a position in Active state locally while the
  corresponding exchange position had already been closed (via liquidation, manual close, or externally-resident insurance stop fill).

  Key Achievement: Zero stale-Active positions can now persist undetected in production.

  ---
  ✨ New Features

  Policy I3 — Reverse Reconciliation Invariant

  Symmetry restored: The runtime now enforces invariants in both directions:

  Direction: Exchange has, Robson does not
  Invariant: I1/I2 (UNTRACKED)
  Detection: Foreign position on operated account
  Action: Close at market (UNTRACKED_ON_EXCHANGE)
  ────────────────────────────────────────
  Direction: Robson Active, Exchange does not
  Invariant: I3 (stale-Active)
  Detection: Local lifecycle drift after external close
  Action: Gather evidence, close locally (ReconciledMissingOnExchange)

  Implementation: TD-2026-05-05-001 Slices 0–5A

  ---
  Startup Stale-Active Gate (Fail-Closed)

  New behavior: When robsond starts, it now checks all local Active positions against the exchange before entering the control loop.

  - Stale-Active detected → Daemon refuses to start (exit code 78)
  - Log severity: CRITICAL per affected position
  - Operator path: Follow runbook docs/runbooks/td-2026-05-05-001-stale-active-recovery.md

  Configuration:
  # Default: abort (fail-closed)
  ROBSON_RECONCILIATION_ON_STARTUP_STALE_ACTIVE=abort

  # Grace period for periodic worker (not used by startup gate)
  ROBSON_RECONCILIATION_MISSING_GRACE_SECS=60  # default

  Rationale: Capital safety > delayed detection. Operator must explicitly resolve any drift before production restart.

  ---
  Evidence-Based Reconciliation

  Every reconciliation-close event carries provable exchange evidence in strict priority order:

  1. OrderFillRecord — Specific exchange order (e.g., resident insurance_stop_id) confirmed FILLED
  2. UserTradeRecord — Per-symbol trade history when no candidate order id is known
  3. AccountSnapshot — Two consecutive snapshots proving position is zeroed (rejected in v2.5)
  4. Estimated — Last resort conservative exit price (rejected in v2.5)

  v2.5 scope (Slice 5A): Only OrderFillRecord and UserTradeRecord auto-close positions. AccountSnapshot and Estimated are explicitly rejected
  to prevent invented PnL.

  Domain type: New ClosureEvidence enum in Event::PositionClosed

  ---
  Active-Only Enforcement

  Safe auto-close scope:
  - Active positions → Auto-close after grace period + second observation
  - Entering positions → Detected, logged, NOT closed (placement latency protection)
  - Exiting positions → Detected, logged, NOT closed (legitimate exit in-flight)

  New events:
  - DaemonEvent::ReconciliationStaleNonActiveDetected — Entering/Exiting drift warning
  - DaemonEvent::ReconciliationStaleActiveUnresolved — No unambiguous real evidence available

  ---
  Grace Period + Second Observation

  False-positive protection:
  1. First observation → Exchange snapshot does not contain expected (symbol, side). Record first_observed_missing_at, no action.
  2. Grace period → Default 60s (configurable via ROBSON_RECONCILIATION_MISSING_GRACE_SECS)
  3. Second consecutive observation → Confirm drift, invoke close path

  Idempotency: Reconciliation runs every 60s; all paths are safe to re-run.

  🚨 Breaking Changes

  None. All changes are backward-compatible:

  - Existing behavior unchanged for normal exit paths
  - New reconciliation logic is additive

  ---
  📦 Upgrade Notes

  From v2.4.x to v2.5.0

  1. No schema migration required — EventLog and projections are backward-compatible
  2. Review startup behavior:
    - If upgrading a running production instance, ensure all local Active positions have exchange counterparts before restart
    - First restart will run the startup gate; any stale-Active → exit 78 → follow runbook
  3. Alerting:
    - Add CRITICAL log filter for Startup gate: Robson-Active position absent from exchange
    - Monitor new Prometheus counter: robson_reconciliation_stale_active_total
  4. Runbook drill (recommended):
    - Exercise docs/runbooks/td-2026-05-05-001-stale-active-recovery.md on testnet
    - Verify operator access to Binance Futures account and evidence collection endpoints

  Environment Variables

  No action required — new variables have safe defaults. To customize:

  # Optional: adjust grace period (default 60s is recommended)
  ROBSON_RECONCILIATION_MISSING_GRACE_SECS=120

  # Startup gate policy (only 'abort' accepted in v2.5)
  ROBSON_RECONCILIATION_ON_STARTUP_STALE_ACTIVE=abort
