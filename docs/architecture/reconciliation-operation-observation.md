## Units and actual boundaries

The review score is reached public SQLx statement attempts + 2 * real HTTP submissions. Threshold >15 emits a monotonic crossing counter and warning without changing financial decisions/protection. There are no per-SQL success/error/cancel claims: statement futures are charged on first poll, once across repolls; root outcome separately records success/error/cancellation. A failed preparation is an attempt even with zero PG Execute messages. BEGIN and COMMIT are explicit attempts. Transaction guards record rollback QUEUED through the public SQLx Drop contract; they do not establish server receipt or acknowledgment. Planned journal counters remain separate.

MemoryStore emits exactly one local call at each actual Position/Order/Event repository method, including failed attempts and writes. Active/risk subset fixture counters are not added again; caller wrappers do not add duplicate local counts. Local work is reported separately from the network score.

The real BinanceRestClient answer boundary counts each reqwest submission; fixed path classes distinguish inventory/conditional/order/open-orders/trades/wallet/price/rules/klines/other. Unknown paths mark attribution incomplete. Venue receipt cannot be concluded from a connection failure. Exchange guardrail weight is two; these metrics do not invent Binance REQUEST_WEIGHT values.

Only an observed reconciliation uses the existing fresh single_shot client: signed Request method/body/headers are preserved, the original gate/signature run before handoff, and the existing request timeout covers execution plus body. Redirect/retry behavior changes intentionally for these requests only: no redirects, no protocol retries, no reused-connection resend. Other client calls retain the legacy transport. Fresh clients trade pooling/TLS connection reuse for one submission per transport request; latency/allocator measurements remain required. No TLS/proxy/resolver policy or timeout is changed.

## Ownership and bounded retention

The metric definition is **observed causal work plus an unowned current physical prefix, explicitly incomplete**. It is not a complete physical flush-job total. Existing intent slots, pending suspension rows and incident versions retain one origin reference. Flush restores observation context, never a financial permit or send grant. A returned foreground call is not a complete observation while pending owned work retains that span. Final summary occurs when references end. Existing metadata-refresh tasks capture their origin before spawn. Scan close append/apply is synchronous in execute_and_persist; independent income DomainEvent production/daemon replay remains independently owned, not attributed to a nearby scan.

A captured false origin is always restored as task-local false under an explicit parentless barrier, never Span::none. Before detaching false work from an ambient measured scan, the ambient observation is marked incomplete; neither transport selection nor counts may silently inherit that later scan. A pending entry with no origin instead keeps its reached physical work on the current scan but marks that scan incomplete before awaiting it. Known old origins restore their own context, count once and do not move to the current caller. These rules change observation only, never the financial permit, business ordering, fence or retry schedule.

Coalescing distinct origins marks BOTH observations incomplete, retains at most the first origin, and attributes physical flush once to that first origin. It does not implement the earlier plan's separate flush-summary alternative. No complete causal total is claimed for either coalesced operation. Pending storage capacities and business retry/deadline behavior are unchanged: intent/suspension pending cap 1024, operation cap32, fixed8 incident reasons. Origins are removed with landed/collected pending work and never stored on the discarded-ID lifetime set. Atomics saturate at u64::MAX and mark incomplete. No identifier is a metric label or observer registry key; endpoint10 and outcome3 label sets are fixed. Source-held spans/atomics are bounded by existing owners; live RSS/allocator trend remains an execution obligation.
